# 검증 기준

변경에 맞는 최소한의 의미 있는 검증을 수행한다.

```sh
npm test
npm run lint
./node_modules/.bin/tsc --noEmit
npm run build
```

- 문서만 수정한 경우에는 링크·경로·내용과 diff를 확인한다. 앱 빌드까지 반복할 필요는 없다.
- 포맷 검사는 변경 파일에 한정해 실행할 수 있다: `./node_modules/.bin/prettier --check <변경 파일>`.
- `npm run format`은 저장소 전체를 수정하므로 무관한 파일까지 포맷하지 않는다.
- `npm test`는 Node 내장 테스트 러너와 tsx로 `tests/*.test.ts`를 실행한다. 실제 동행복권 네트워크 없이 응답·시간을 주입해 데이터 검증·부분 실패·타임아웃·캐시 상태를 검사한다. 새 비즈니스 규칙에는 의미 있는 회귀 테스트를 추가한다.
- UI 변경은 320px·390px·1280px, 키보드 조작, 포커스, 오류·빈 상태, 축소 모션을 확인한다.
- 빌드에는 외부 폰트 조회가 필요할 수 있다. 네트워크·권한으로 검증이 막히면 원인과 실행하지 못한 검증을 구분해서 보고한다. 검사를 통과시키려고 폰트나 보안 설정을 임의 변경하지 않는다.
- 기존 실패와 새로 생긴 실패를 구분한다. 실행 결과 없이 완료·통과·배포 성공을 주장하지 않는다.

- DB 아카이브 테스트는 PGlite의 격리된 실제 PostgreSQL 엔진에 마이그레이션을 적용해 CHECK·GRANT/SET ROLE·원자 저장·lease/fencing·일일 예산·백오프·보존기간·DDL 롤백을 검증한다. 생성 직후 `pg_table_size`/`pg_indexes_size` baseline을 출력한다. Neon 운영 용량·사용량 실측으로 해석하지 않는다.
- PGlite는 단일 연결이므로 여러 Neon 세션 사이의 실제 잠금 경합, Neon HTTP 드라이버/자격·Preview별 브랜치 연결, Vercel 출발 네트워크는 별도 격리 Neon 환경에서 확인해야 한다. 로컬 테스트는 이 제한을 숨기지 않는다. 원천 응답은 주입하므로 테스트에서 공식 사이트를 호출하지 않는다.
